# Часть I. Теория

## 1. Задача и данные

**Задача.** Классификация изображений: по картинке 28×28 выбрать один класс из 11 — цифры 0–9 и «не цифра».

**MNIST.** 70 000 чёрно-белых картинок рукописных цифр 28×28. Стандартное разбиение: 60 000 обучающих и 10 000 тестовых. Цифры в нём вписаны в рамку 20×20 и расположены по центру масс внутри поля 28×28. Это важно для раздела 10.

**Представление.** Картинка — матрица 28×28 чисел 0–255. Полносвязной сети нужен вектор, поэтому строки склеиваются в вектор из 784 чисел. Затем значения делятся на 255 и попадают в диапазон [0, 1]. Масштаб входов влияет на масштаб градиентов и на подходящий learning rate; значения порядка единицы удобны для обучения.

**Метки.** Целые числа 0..10. В коде они используются как индексы (`probs[np.arange(n), y]`), one-hot векторы не строятся.

**Три выборки.**

| Выборка | Размер в проекте | Роль | Меняет веса |
|---|---|---|---|
| train | 50 000 цифр + «не цифры» | учиться | да |
| val | 10 000 цифр + «не цифры» | сравнивать настройки (lr, размер слоя, число эпох) | нет |
| test | 10 000 цифр + 1 000 «не цифр» | финальная оценка, один раз | нет |

Если подбирать настройки по test, оценка перестаёт быть честной: решение оказывается подогнано под test.

**Баланс классов.** В MNIST цифр примерно поровну (около 10% на класс), поэтому accuracy осмысленна. «Не цифр» в обучении около 9% (5 000 из 55 000). Для сильно несбалансированных задач нужны другие метрики (раздел 9).

**Память.** 70 000 × 784 байт ≈ 55 МБ в `uint8` против ≈ 439 МБ в `float64`. Поэтому данные хранятся как `uint8`, а в дробные числа переводятся порциями (`to_input`).

## 2. Нейрон, слой, сеть

**Нейрон** считает взвешенную сумму входов и пропускает её через функцию активации:

```
z = w · x + b            # скалярное произведение + смещение
a = f(z)                 # f - функция активации
```

**Слой** — много нейронов, считающихся одновременно как умножение матриц. Для порции из `n` картинок:

```
z1    = x @ W1 + b1      # (n, 784) @ (784, 128) + (128,)  ->  (n, 128)
a1    = relu(z1)         # (n, 128)
z2    = a1 @ W2 + b2     # (n, 128) @ (128, 11) + (11,)    ->  (n, 11)
probs = softmax(z2)      # (n, 11), в каждой строке сумма = 1
```

Столбец `W1[:, j]` — «шаблон» j-го скрытого нейрона: 784 коэффициента, по одному на пиксель. Нейрон тем сильнее активируется, чем больше входная картинка похожа на его шаблон. Шаблоны можно нарисовать как картинки 28×28 (хорошая идея для улучшения проекта).

**Число параметров.**

```
W1: 784 * 128 = 100 352     b1: 128
W2: 128 * 11  =   1 408     b2: 11
Итого: 101 899
```

**Зачем нелинейность.** Без неё несколько слоёв схлопываются в один: `(x @ W1) @ W2 = x @ (W1 @ W2)`. Сеть умела бы только линейно разделять классы. Функция активации делает композицию слоёв гибкой.

**ReLU:** `relu(z) = max(0, z)`. Производная: 1 при `z > 0`, иначе 0.

| Активация | Плюсы | Минусы |
|---|---|---|
| ReLU | дёшево считается, градиент не затухает при `z > 0` | «мёртвые» нейроны: если `z ≤ 0` для всех входов, градиент через нейрон нулевой и он не учится |
| sigmoid, tanh | гладкие, ограниченные | насыщаются при большом по модулю `z`, градиент почти 0 (vanishing gradient), в глубоких сетях это тормозит обучение |

**Скрытый слой как извлечение признаков.** Первый слой превращает 784 пикселя в 128 признаков («есть ли здесь дуга сверху», «есть ли вертикальная черта»), второй слой по признакам выбирает класс. Эти признаки не задаются руками, они находятся при обучении.

**Универсальная аппроксимация.** Сеть с одним скрытым слоем и достаточным числом нейронов может приблизить любую непрерывную функцию на ограниченной области с любой точностью. Теорема ничего не говорит о том, сколько нейронов нужно и найдёт ли градиентный спуск такие веса. На практике важны архитектура и данные: для картинок свёрточные сети заметно эффективнее полносвязных (раздел 12).

## 3. Softmax и вероятности

Выход `z2` — 11 произвольных чисел («очки»). Softmax превращает их в вероятности:

```
p_i = exp(z_i) / sum_j exp(z_j)
```

Свойства:
- все `p_i > 0` и `sum p_i = 1`;
- сохраняет порядок: больше очков — больше вероятность;
- **не меняется при сдвиге всех `z` на одну константу**: `softmax(z) = softmax(z - c)`.

Последнее используется для устойчивости. `exp(1000)` переполняет float, поэтому из каждой строки вычитается её максимум:

```python
z = z - z.max(axis=1, keepdims=True)    # теперь максимум равен 0, exp(z) не больше 1
e = np.exp(z)
return e / e.sum(axis=1, keepdims=True)
```

Проверка `softmax_sums_to_one_and_is_stable` подаёт числа порядка 1000.

**Softmax и sigmoid.** Softmax выбирает один класс из взаимоисключающих (цифра либо одна, либо другая). Если объекту можно присвоить несколько меток одновременно (multi-label), для каждой метки используют отдельную sigmoid.

**«Вероятность» не равна уверенности.** Softmax всегда распределяет 100% между имеющимися классами. Выход 0.98 означает «этот вариант намного лучше остальных», а не «сеть почти наверняка права». Подробно в разделе 11.

## 4. Функция потерь

Нужно одно число, которое показывает, насколько сеть ошибается, и по которому можно считать градиент. Для классификации берут **cross-entropy**:

```
L = -log(p_y)            # p_y - вероятность, которую сеть дала правильному классу
```

Для порции берётся среднее по картинкам:

```python
-np.mean(np.log(probs[np.arange(n), y] + 1e-12))
```

`1e-12` защищает от `log(0)`.

| `p_y` | 0.99 | 0.5 | 0.1 | 0.01 |
|---|---|---|---|---|
| `L` | 0.01 | 0.69 | 2.30 | 4.61 |

**Контроль на старте.** При случайных весах сеть примерно угадывает: loss должен быть порядка `ln 11 ≈ 2.4`. Если на первой эпохе получается 0 или тысячи, ошибка в коде или в масштабе данных.

**Почему cross-entropy, а не ошибка.**

1. *Максимальное правдоподобие.* Минимизировать `-log p_y` по всем примерам — то же самое, что максимизировать вероятность наблюдаемых меток при данной модели. Это естественная статистическая постановка.
2. *Accuracy нельзя оптимизировать градиентом:* она меняется скачками, её производная почти везде нулевая.
3. *MSE по выходам softmax учится хуже.* Её градиент содержит множитель `p(1 - p)`: если сеть уверенно ошибается (`p` близко к 0 или 1), градиент почти исчезает. В cross-entropy этот множитель сокращается с производной softmax, остаётся `p - y` (раздел 5).

## 5. Обратный проход (backprop)

**Цель:** для каждого веса узнать, как он влияет на `L` (градиент `dL/dW`), чтобы сдвинуть вес в сторону уменьшения `L`.

**Идея.** Сеть — цепочка операций. По цепному правилу производная по параметру раннего слоя получается умножением производных всех операций после него. Backprop считает их от конца к началу и переиспользует промежуточные результаты. Поэтому `forward` сохраняет `(x, z1, a1)`.

### Шаг 1. Градиент на выходе (softmax + cross-entropy)

Для одного примера производная softmax: `dp_i/dz_j = p_i (δ_ij - p_j)`, где `δ_ij = 1` при `i = j`, иначе 0. Для `L = -Σ y_i log p_i` (`y` — one-hot):

```
dL/dz_j = Σ_i (-y_i / p_i) * p_i (δ_ij - p_j)
        = -y_j + p_j * Σ_i y_i
        = p_j - y_j
```

**Градиент = предсказанные вероятности минус правильный ответ (0/1).** Если сеть уверена в правильном классе (`p_y ≈ 1`), градиент почти нулевой. В коде:

```python
dz2 = probs.copy()
dz2[np.arange(n), y] -= 1.0      # вычли 1 у правильного класса
dz2 /= n                         # усреднение по порции
```

### Шаг 2. Линейный слой `z = a @ W + b`

Пусть `G = dL/dz` — градиент, пришедший сверху. Поэлементно `z_ij = Σ_k a_ik W_kj + b_j`, откуда:

```
dW = a.T @ G             # (in, n) @ (n, out) = (in, out)   форма как у W
db = G.sum(axis=0)       # (out,)
da = G @ W.T             # (n, out) @ (out, in) = (n, in)    градиент для предыдущего слоя
```

Правило для проверки: **форма градиента всегда равна форме самого параметра**.

### Шаг 3. ReLU

```
dz1 = da1 * (z1 > 0)     # где нейрон «молчал» (z1 <= 0), градиент не проходит
```

### Шаг 4. Первый слой

Те же формулы, что в шаге 2, с `a = x`:

```
dW1 = x.T @ dz1          # (784, n) @ (n, 128) = (784, 128)
db1 = dz1.sum(axis=0)    # (128,)
```

Градиент по `x` не нужен: входы не обучаются.

### Итоговая таблица

| Величина | Формула | Форма |
|---|---|---|
| `dz2` | `(probs - onehot(y)) / n` | (n, 11) |
| `dW2` | `a1.T @ dz2` | (128, 11) |
| `db2` | `dz2.sum(0)` | (11,) |
| `da1` | `dz2 @ W2.T` | (n, 128) |
| `dz1` | `da1 * (z1 > 0)` | (n, 128) |
| `dW1` | `x.T @ dz1` | (784, 128) |
| `db1` | `dz1.sum(0)` | (128,) |

Стоимость: backward содержит по два умножения матриц на слой (для `dW` и для `da`), то есть примерно вдвое дороже forward.

### Проверка градиента (gradient check)

Аналитические формулы легко записать с ошибкой, которая не вызовет исключения, а просто испортит обучение. Поэтому градиент сверяют с численным, считаемым по определению через центральную разность:

```
dL/dw ≈ (L(w + ε) - L(w - ε)) / (2ε)         ε = 1e-5
```

Ошибка такой оценки порядка `ε²`. Критерий: относительная ошибка `max|аналит. - числ.| / max|аналит.|` меньше `1e-5` (в проекте получается порядка `1e-9`). Подводные камни:
- `ε` слишком малое: ошибки округления float; слишком большое: ошибка аппроксимации;
- ReLU негладкая в нуле: при случайных данных точка 0 почти никогда не попадается, но возможны редкие ложные срабатывания;
- проверку делают на маленькой сети и случайных данных; для больших матриц достаточно выборки элементов (так сделано в `check.py`).

## 6. Пример на числах

Мини-сеть: 2 входа → 2 скрытых нейрона → 3 класса, один пример, правильный класс `y = 2`. Все числа проверены кодом проекта.

```
x  = [1.0, 2.0]
W1 = [[ 0.5, -1.0],      b1 = [0.0, 0.5]
      [ 0.25, 0.5]]
W2 = [[ 1.0, -0.5,  0.2],   b2 = [0, 0, 0]
      [ 0.3,  0.8, -1.0]]
```

**Forward.**

```
z1    = x @ W1 + b1  = [1*0.5 + 2*0.25,  1*(-1) + 2*0.5] + [0, 0.5] = [1.0, 0.5]
a1    = relu(z1)     = [1.0, 0.5]
z2    = a1 @ W2 + b2 = [1.15, -0.10, -0.30]
probs = softmax(z2)  = [0.6574, 0.1884, 0.1542]
L     = -ln(0.1542)  = 1.8694
```

Правильный класс получил только 15%, поэтому штраф большой.

**Backward.**

```
dz2 = probs - onehot = [0.6574, 0.1884, 0.1542 - 1] = [0.6574, 0.1884, -0.8458]
dW2 = a1.T @ dz2     = [[0.6574, 0.1884, -0.8458],       (строка a1[0] = 1.0)
                        [0.3287, 0.0942, -0.4229]]       (строка a1[1] = 0.5)
db2 = dz2
da1 = dz2 @ W2.T     = [0.3941, 1.1937]
dz1 = da1 * (z1 > 0) = [0.3941, 1.1937]                  (оба нейрона активны)
dW1 = x.T @ dz1      = [[0.3941, 1.1937],                (x[0] = 1)
                        [0.7882, 2.3874]]                (x[1] = 2)
db1 = dz1
```

Сверка с численным градиентом: максимальное расхождение порядка `1e-10`.

**Шаг при `lr = 0.5`.** Веса сдвигаются на `-0.5 * градиент`. Например, `W2[0, 2]` становится `0.2 + 0.5 * 0.8458 = 0.6229`.

```
loss до шага:   1.8694
loss после:     0.7265
probs после:    [0.2281, 0.2883, 0.4836]     # правильный класс вырос с 15% до 48%
```

Один шаг резко уменьшил loss, потому что `lr = 0.5` и пример всего один. На реальных данных шаги мелкие и их сотни тысяч.

## 7. Оптимизация

**Градиентный спуск.** Каждый параметр сдвигается против градиента:

```
w = w - lr * dL/dw
```

`lr` (learning rate) — размер шага. Слишком маленький: обучение медленное. Слишком большой: шаги перепрыгивают минимум, loss скачет или растёт, возможны `nan`. Типичные значения для такой сети лежат между 0.01 и 0.5; в проекте по умолчанию 0.1.

**Stochastic и mini-batch.** Полный градиент по 50 000 картинкам дорог; по одной картинке шумный. Mini-batch (по умолчанию 64) — компромисс.

| Размер порции | Скорость шага | Шум градиента | Замечание |
|---|---|---|---|
| маленький (1–16) | дёшево, но мало параллелизма | большой | много шагов за эпоху |
| средний (32–256) | хороший баланс | умеренный | значение по умолчанию |
| большой (тысячи) | дорого, меньше шагов за эпоху | малый | нужна память, иногда другой `lr` |

Шум градиента не только мешает, но и считается полезным: он помогает не застревать в плохих областях.

**Эпоха** — один проход по всем обучающим картинкам. В начале каждой эпохи данные перемешиваются, чтобы порядок не создавал закономерностей. Эпоха в проекте: 55 000 / 64 ≈ 860 шагов.

**Инициализация весов.**
- *Нулями нельзя:* все нейроны скрытого слоя получали бы одинаковые градиенты и навсегда оставались одинаковыми (проблема симметрии).
- *Слишком большие:* сигналы раздуваются, softmax насыщается, ReLU-сети «взрываются».
- *He-инициализация:* `W ~ N(0, 2/n_in)`. Вывод: `Var(z) = n_in * Var(w) * E[x²]`; для ReLU `E[a²] = Var(z)/2`; чтобы масштаб сигнала сохранялся от слоя к слою, нужно `Var(w) = 2 / n_in`. Для tanh и sigmoid берут Xavier: `2 / (n_in + n_out)`.
- Смещения начинают с нуля.

**Что не реализовано, но стоит знать.**

*Momentum:* накапливается «скорость», шаг сглаживается: `v = β·v + g; w -= lr·v`.

*Adam:* адаптивный шаг для каждого параметра.

```
m = β1·m + (1 - β1)·g          v = β2·v + (1 - β2)·g²
m̂ = m / (1 - β1^t)             v̂ = v / (1 - β2^t)
w = w - lr · m̂ / (√v̂ + ε)      β1 = 0.9, β2 = 0.999, ε = 1e-8
```

*Расписание lr:* уменьшать шаг к концу обучения.

**Как читать кривые обучения.**

| Картина | Диагноз | Что делать |
|---|---|---|
| train loss падает, val loss тоже | нормально | продолжать |
| train падает, val растёт | переобучение | меньше эпох, регуляризация, больше данных |
| оба высокие и почти не падают | недообучение или `lr` слишком мал | больше нейронов, больше эпох, увеличить `lr` |
| loss скачет или `nan` | `lr` слишком велик | уменьшить `lr` |

## 8. Обобщение и переобучение

Цель — не запомнить обучающие картинки, а хорошо работать на **новых**. Поэтому качество всегда смотрят на данных, которых сеть не видела.

**Переобучение (overfitting):** сеть подгоняется под особенности обучающих примеров, включая шум. Признак: train accuracy растёт, а val accuracy стоит или падает. **Недообучение:** сеть слишком проста или обучена слишком мало, плохо и на train, и на val.

**Bias–variance.** Ошибка складывается из смещения (модель слишком проста, чтобы описать закономерность) и разброса (модель слишком чувствительна к конкретной обучающей выборке). Рост сложности (больше нейронов, больше эпох) уменьшает смещение, но увеличивает разброс.

**Способы борьбы с переобучением.**

| Способ | Идея | Как выглядит |
|---|---|---|
| Больше данных, аугментация | больше разнообразия | сдвиги, повороты, шум для картинок |
| L2-регуляризация (weight decay) | штраф за большие веса | `L' = L + (λ/2)·Σ‖W‖²`, градиент получает слагаемое `λ·W` |
| Dropout | случайно «выключать» нейроны при обучении | `a = a * mask / (1 - p)`, `mask ~ Bernoulli(1 - p)`; при предсказании выключен |
| Ранняя остановка | остановить обучение, когда val loss перестал падать | запомнить лучшие веса по val |
| Меньше сеть | меньше возможностей запоминать | `--hidden 32` |

**Утечка данных (data leakage)** — когда информация о проверочных данных попадает в обучение. Примеры: подбор гиперпараметров по test; нормировка по статистике всех данных вместе; одинаковые картинки в train и test. Утечка завышает оценку, и на реальных данных результат оказывается хуже.

**Проверка «выучит ли одну маленькую порцию».** Если сеть не может довести loss почти до нуля на 500 примерах, в обучении ошибка. Это делает проверка `network_can_learn`.

## 9. Метрики

**Accuracy** — доля верных ответов. Просто, но обманчиво при несбалансированных классах.

**Confusion matrix** `cm[истина, предсказание]`: строки — настоящий класс, столбцы — ответ сети. Диагональ — верные ответы, вне диагонали — виды ошибок (какие цифры путаются).

```python
cm = np.zeros((11, 11), dtype=int)
np.add.at(cm, (y_true, y_pred), 1)
```

**Precision и recall** для класса `k`:

```
precision_k = cm[k, k] / cm[:, k].sum()    # из всего, что сеть назвала k, какая доля верна
recall_k    = cm[k, k] / cm[k, :].sum()    # из всего, что на самом деле k, какую долю нашли
F1_k        = 2 · precision · recall / (precision + recall)
```

Для усреднения по классам: *macro* (все классы равноправны) и *micro* (считаются все примеры вместе).

**Когда accuracy обманывает.** В банке 1 мошенническая операция на 1000. Модель, всегда отвечающая «не мошенничество», имеет accuracy 99.9% и recall по мошенничеству 0. Здесь важны recall (сколько мошенничества поймали), precision (сколько ложных тревог) и цена каждой ошибки. Порог принятия решения подбирают под эту цену, часто по precision–recall кривой.

**Loss и accuracy — разные вещи.** Loss учитывает уверенность: два ответа с верным классом, но с вероятностью 0.51 и 0.99, дают одинаковую accuracy и разный loss. Бывает, что val accuracy растёт, а val loss начинает расти: сеть ошибается реже, но когда ошибается — слишком уверенно.

**В проекте:** `train.py` печатает loss и accuracy на train и val по эпохам, а в конце — accuracy на test для цифр, долю ответов «не знаю» с порогом и долю распознанных «не цифр» (раздел 11).

## 10. Подготовка рисунка: данные «в поле» против обучающих

Сеть училась на картинках MNIST. Если подать ей картинку, подготовленную иначе, качество падает, хотя код работает без ошибок. Это называют сдвигом данных (distribution shift, train/serve skew).

Рисунок мышью отличается от MNIST: поле 280×280 вместо 28×28, цифра может быть любого размера и в любом месте, штрих другой толщины. Поэтому `preprocess` приводит его к конвенции MNIST:

1. **Обрезка** по границам закрашенной области (`pixels > 0.1`).
2. **Масштаб:** длинная сторона становится 20 пикселей, пропорции сохраняются. Масштабирование идёт усреднением: каждому новому пикселю соответствует прямоугольник старых, берётся его средняя яркость. Суммы по прямоугольникам считаются быстро через накопленные суммы (integral image): `S[i, j] = сумма a[:i, :j]`, сумма прямоугольника = `S[y1,x1] - S[y0,x1] - S[y1,x0] + S[y0,x0]`.
3. **Размещение** в центре поля 28×28.
4. **Центр масс.** Яркость играет роль массы:
   ```
   cy = Σ_i i · (сумма яркости строки i) / Σ яркости        cx - аналогично по столбцам
   ```
   Картинка сдвигается на `round(13.5 - cy)`, `round(13.5 - cx)` (13.5 — центр поля 28 пикселей при нумерации с нуля), сдвиг ограничен ±4, чтобы цифра не вышла за край.

Проверки в `check.py`: форма результата и вписанность в 20×20; центр масс рядом с центром; **большая, маленькая и смещённая фигура дают почти одинаковую картинку**.

**Что остаётся неидеальным.** Толщина штриха и наклон не нормируются; кисть фиксированного радиуса даёт более «жирные» цифры для маленьких рисунков. Рисуйте цифры крупно.

## 11. «Не знаю»: класс «не цифра» и отказ от ответа

### Почему сеть уверенно называет цифру, когда рисуешь букву

1. **Закрытая задача.** Softmax делит 100% вероятности между имеющимися классами. Если классов 10, сеть обязана выбрать цифру: варианта «ничего из этого» нет.
2. **Сеть не знает границ своих знаний.** Нейросети склонны быть излишне уверенными на данных, не похожих на обучающие (проблема калибровки уверенности). Картинки не из обучающего распределения называют out-of-distribution (OOD), а задачу различения «известное / неизвестное» — open-set recognition.

### Подходы

| Подход | Суть | Плюсы | Минусы |
|---|---|---|---|
| Порог уверенности (reject option) | `max(probs) < 0.7` → «не знаю» | без переобучения, одна строка (`decide`) | сеть может быть уверенно неправа, тогда порог не спасает |
| Дополнительный класс (outlier exposure) | учить 11-й выход на примерах не-цифр | сеть сама учится отличать | нужны примеры «не цифр», их разнообразие ограничено |
| Калибровка (temperature scaling) | делить `z2` на температуру `T`, подобранную на val | вероятности ближе к частотам | не решает проблему OOD сама по себе |
| Отдельный детектор аномалий | другая модель | гибко | сложнее |

В проекте используются первые два (калибровка и детектор — идеи на будущее).

### Откуда берутся «не цифры»

`unknown.py` генерирует картинки без скачивания датасетов:
- **буквы** штриховым шрифтом (отрезки в квадрате 1×1) с случайной шириной, наклоном, поворотом и «дрожью руки» — 50% примеров;
- **каракули:** случайные ломаные из 5–10 точек — 40%;
- **кляксы:** сплошные пятна — 10%.

Они рисуются той же кистью и проходят через ту же `preprocess`, что и рисунки из окошка, поэтому для сети выглядят одинаково.

Буквы **O, I, l, S, Z, B, G** намеренно не используются: они реально похожи на 0, 1, 5, 2, 8, 6, и пометка их «не цифрой» создала бы противоречивые обучающие данные.

### Как «не знаю» принимается в коде

`decide(probs, threshold=0.7)` возвращает «не цифра» (10), если сеть выбрала класс 10 **или** максимум вероятности ниже порога. Эта функция используется в отчёте `train.py`. Окошко `app.py` вердикт не выносит: оно показывает вероятности всех 11 классов и выделяет синим максимум.

### Эксперимент (на искусственных данных)

На настоящем MNIST это проверить не удалось, поэтому эксперимент поставлен на искусственных данных: цифры нарисованы штриховым шрифтом, а в проверку добавлены буквы P, T, J, L, D, которых сеть при обучении не видела.

| Вариант | Цифры верно (с порогом) | Невиданные буквы отвергнуты |
|---|---|---|
| только порог 0.5 / 0.7 / 0.9 | 99.9% / 99.6% / 98.7% | 23% / 48% / 72% |
| класс «не цифра» + порог 0.5 / 0.7 / 0.9 | 99.7% / 99.2% / 97.3% | 68% / 76% / 82% |

Выводы:
- Класс «не цифра» сильнее всего поднимает долю отвергнутых букв при одном и том же пороге (при 0.7 с 48% до 76%), а цена — доли процента цифр.
- Порог без класса можно довести до сопоставимого результата (72% при 0.9), но тогда теряется больше настоящих цифр.
- Увеличение числа примеров «не цифра» сверх ~10% от числа цифр почти ничего не добавляет.
- После добавления буквы T в генератор она стала отвергаться в 96% случаев вместо 67%, а точность на семёрках не изменилась (99.3%).
- Оценка «узнано как не цифра» в `train.py` считается на картинках из того же генератора и оптимистична. Настоящий критерий — собственные рисунки.

Эти числа относятся к искусственным данным. На настоящем рукописном вводе они будут другими.

**Практический смысл.** В продакшене (например, в банке) модель постоянно получает данные, не похожие на обучающие. Важно уметь это заметить и передать человеку, а не отвечать уверенно и неверно.

## 12. Ограничения и что дальше

**Ограничения этой модели.**
- Полносвязная сеть смотрит на пиксели «по отдельности» и не знает, что соседние пиксели связаны. Поэтому она чувствительна к стилю письма и небольшим сдвигам.
- Обычно такая сеть даёт около 97–98% на MNIST. Свёрточные сети на этом датасете достигают порядка 99% и выше.
- MNIST — аккуратные цифры; рисунки мышью отличаются, поэтому результат в окошке бывает хуже, чем на тесте.

**Что улучшать (по возрастанию сложности).**

1. Подобрать порог: таблица «порог → доля отклонённых цифр → доля отклонённых букв».
2. Confusion matrix и разбор ошибок на тесте.
3. Визуализировать веса `W1` как картинки 28×28.
4. Эксперименты по `lr`, `hidden`, `batch-size` с таблицей результатов.
5. Momentum или Adam в `Network.step`.
6. L2 или dropout; сравнить val loss.
7. Аугментация: случайные сдвиги картинок при обучении.
8. Второй скрытый слой: веса в списке, циклы в `forward`/`backward`/`step`.
9. Реальные буквы (датасет EMNIST Letters) вместо сгенерированных.
10. Свёрточная сеть (PyTorch): локальные фильтры с общими весами учитывают структуру изображения.
11. Калибровка вероятностей (temperature scaling).

## 16. Что происходит при `python train.py`

1. Разбор аргументов; значения проверяются (`--epochs 0` отвергается).
2. `load_mnist()`; при первом запуске скачивание в `data/mnist.npz`.
3. Если задан `--samples N`, берутся первые `N` обучающих цифр.
4. Число «не цифр»: `--unknown` или 10% от числа цифр (5 000 для 50 000).
5. `build_training_set`: 50 000 цифр + 5 000 «не цифр» = 55 000 картинок, перемешаны.
6. Для val добавляется доля «не цифр» в том же соотношении (1 000), для test — отдельные 1 000 (`seed=3`).
7. `Network(n_hidden)` — случайные He-веса.
8. Цикл по эпохам. В каждой эпохе:
   - новая случайная перестановка индексов;
   - по порциям `batch_size`: `to_input` → `forward` → `backward` → `step`;
   - после эпохи `evaluate` на train (10 000) и на val, печать строки; если loss стал `nan` или `inf`, выход с подсказкой уменьшить `--lr`.
9. `report` на test.
10. `Network.save()` → `model.npz`.

Эпоха: 55 000 / 64 ≈ 860 шагов.

## 19. Проектные решения

| Решение | Причина | Цена |
|---|---|---|
| Только NumPy | видно каждую формулу, нет тяжёлых зависимостей, работает на любом CPU | медленнее, чем на PyTorch/GPU; нет автоматического градиента |
| Один скрытый слой | достаточно для ~97–98% и легко разбирается | потолок качества ниже, чем у свёрточных сетей |
| Backprop вручную + gradient check | понимание механики и гарантия правильности | при изменении архитектуры формулы придётся писать заново |

| Оценка порциями (`probabilities`) | не создаёт гигантские массивы | чуть более сложный код |
| He-инициализация | подходит для ReLU, стабильный старт | — |
| Метка «не цифра» как 11-й класс | сеть сама учится отказываться | нужны примеры «не цифр», они сгенерированы |
| Генератор «не цифр» без скачивания | проект остаётся лёгким | генератор не равен реальности, оценка оптимистична |

| Пути через `pathlib` от файла модуля | запуск из любой папки, работает на разных ОС | — |

# Часть III

## 21. Вопросы для собеседования

### Основы

**Что такое нейрон и слой?**
Нейрон считает `a = f(w · x + b)`. Слой — много нейронов, вычисляемых одним умножением матриц: `a = f(x @ W + b)`.

**Зачем нужна функция активации?**
Без неё несколько линейных слоёв эквивалентны одному (`(x @ W1) @ W2 = x @ (W1 @ W2)`), и сеть умеет только линейное разделение. Нелинейность (здесь ReLU) даёт сложные границы между классами.

**Чем ReLU лучше sigmoid в скрытых слоях?**
Дешевле считается и не насыщается при `z > 0`, поэтому градиент не затухает. Недостаток — «мёртвые» нейроны, у которых `z ≤ 0` на всех входах и градиент нулевой.

**Что делает softmax? Почему вычитают максимум?**
Превращает вектор очков в вероятности (положительные, сумма 1). Результат не меняется при сдвиге всех очков на константу, а `exp` больших чисел переполняется, поэтому вычитают максимум строки.

**Что такое cross-entropy и откуда она берётся?**
`L = -log p_y`. Это отрицательный логарифм правдоподобия правильных меток: минимизация loss — максимизация вероятности данных при модели. Штрафует уверенные ошибки очень сильно.

**Почему не MSE для классификации?**
У MSE поверх softmax градиент содержит множитель `p(1 - p)` и затухает, когда сеть уверенно ошибается. В cross-entropy он сокращается, остаётся `p - y`.

**Почему градиент softmax + cross-entropy равен `p - y`?**
`L = -z_y + log Σ e^{z_j}`. Производная первого члена — `-[i = y]`, второго — `p_i`. Вместе: `p_i - [i = y]`.

### Обучение

**Объясни backprop простыми словами.**
Это эффективный способ посчитать, как каждый вес влияет на ошибку. Идём от выхода к входу, по цепному правилу передаём градиент слой за слоём, переиспользуя значения из прямого прохода. Затем веса сдвигаются против градиента.

**Как проверить, что backprop написан верно?**
Gradient check: сравнить с численным градиентом `(L(w + ε) - L(w - ε)) / 2ε`. Относительная ошибка должна быть порядка `1e-7` или меньше.

**Что такое learning rate? Что будет, если он слишком большой или слишком маленький?**
Размер шага градиентного спуска. Большой: loss скачет или растёт, возможны `nan`. Маленький: обучение очень медленное.

**Зачем mini-batch?**
Компромисс между стоимостью и шумом: быстрее и стабильнее одного примера, дешевле полного прохода. Шум градиента даже полезен для выхода из плохих областей.

**Что такое эпоха? Почему данные перемешивают?**
Один проход по всем обучающим данным. Перемешивание убирает зависимость от порядка примеров.

**Почему нельзя инициализировать веса нулями?**
Все нейроны слоя получали бы одинаковые градиенты и оставались бы одинаковыми (проблема симметрии). Случайная инициализация её ломает; He-инициализация (`2/n_in`) сохраняет масштаб сигнала для ReLU.

**Что такое vanishing и exploding gradients?**
Градиент, умножаясь по цепочке слоёв, может стать очень малым (насыщающиеся sigmoid/tanh) или очень большим. Помогают ReLU, правильная инициализация, нормализация, остаточные связи.

**Чем Adam отличается от обычного SGD?**
Хранит скользящие средние градиента (`m`) и его квадрата (`v`) и масштабирует шаг для каждого параметра отдельно: `lr · m̂ / (√v̂ + ε)`. Обычно меньше требует подбора `lr`.

### Данные, метрики, обобщение

**Что такое overfitting и как его заметить?**
Сеть запоминает обучающие данные вместо общих закономерностей. Признак: train accuracy растёт, а val accuracy стоит или падает (val loss растёт). Лечат: больше данных и аугментация, L2, dropout, ранняя остановка, меньшая сеть.

**Зачем три выборки: train, val, test?**
train — учиться, val — выбирать настройки, test — один раз честно оценить итог. Выбор по test делает оценку завышенной.

**Что такое data leakage? Пример.**
Попадание информации о проверочных данных в обучение: подбор гиперпараметров по test, нормировка по статистике всех данных вместе, дубликаты между train и test.

**Почему accuracy бывает плохой метрикой?**
При несбалансированных классах (мошенничество 0.1%) модель «всегда нет» даёт accuracy 99.9% и recall 0. Нужны precision, recall, F1 и учёт цены ошибок.

**Как читать confusion matrix? Как из неё получить precision и recall?**
Строки — настоящий класс, столбцы — ответ. `precision_k = cm[k,k] / сумма столбца k`, `recall_k = cm[k,k] / сумма строки k`.

**Может ли val accuracy расти, когда val loss растёт?**
Да: сеть реже ошибается, но ошибается всё увереннее, а loss сильно штрафует уверенные ошибки.

### По проекту

**Расскажи про свой проект в двух предложениях.**
Нейросеть на NumPy (784 → 128 → 11) для MNIST: forward, backprop и SGD написаны вручную, градиент сверен с численным. Есть окно, в котором можно нарисовать цифру, и класс «не цифра» для букв и каракуль.

**Что взял из видео 3Blue1Brown, а что сделал сам?**
Идея и базовая структура сети из видео. Сам: реализация на NumPy с проверкой градиента, mini-batch обучение, разбиение на train/val/test, предобработка рисунков, класс «не цифра» и порог, окошко и набор автоматических проверок. Если спросят, что подсмотрел, говорить прямо.

**Почему рисунок мышью нельзя просто сжать до 28×28?**
Сеть училась на цифрах, вписанных в рамку 20×20 и отцентрованных по центру масс. Другой размер или положение — другой вход, и качество падает. Поэтому рисунок обрезается, масштабируется и центрируется так же.

**Почему сеть называла буквы цифрами? Что сделали?**
У сети было 10 выходов, softmax обязан выбрать одну из цифр, а на незнакомых данных сети склонны к излишней уверенности. Добавлен 11-й класс «не цифра» (учится на сгенерированных буквах и каракулях) и порог уверенности. Компромисс измерен: доля отвергнутых букв против доли отвергнутых настоящих цифр.

**Почему в «не цифрах» нет букв O и I?**
Они визуально неотличимы от 0 и 1. Пометка их «не цифрой» дала бы противоречивые данные, и сеть стала бы отвергать настоящие нули и единицы.

**Как ты оценил, что класс «не цифра» помогает? В чём слабость оценки?**
На искусственных данных с невиданными буквами: при пороге 0.7 доля отвергнутых букв выросла с 48% до 76%, точность на цифрах почти не изменилась. Слабость: данные искусственные, а оценка внутри `train.py` использует тот же генератор, что и обучение; настоящий критерий — реальные рисунки.

**Что бы улучшил дальше?**
Свёрточную сеть, аугментацию, Adam, реальные буквы (EMNIST), калибровку вероятностей, анализ ошибок через confusion matrix.

**Чем твоя реализация отличается от PyTorch?**
Результат тот же. PyTorch считает градиенты автоматически (autograd): весь мой `backward` заменяется `loss.backward()`, а `step` — `optimizer.step()`.

## 22. Глоссарий

| Термин | Значение |
|---|---|
| Epoch (эпоха) | один проход по всем обучающим данным |
| Batch / mini-batch | порция примеров, по которой считается один шаг |
| Learning rate | размер шага градиентного спуска |
| Loss | число, показывающее, насколько сеть ошибается; его минимизируют |
| Gradient | вектор производных loss по параметрам; указывает направление роста |
| Backpropagation | вычисление градиентов от выхода к входу по цепному правилу |
| Activation | нелинейная функция после линейного слоя (ReLU, sigmoid, tanh) |
| Logits | выход сети до softmax (`z2`) |
| Softmax | превращение logits в вероятности |
| Cross-entropy | `-log` вероятности правильного класса |
| One-hot | вектор из нулей с единицей на месте правильного класса |
| Overfitting | подгонка под обучающие данные, плохая работа на новых |
| Regularization | приёмы против переобучения (L2, dropout, ранняя остановка) |
| Validation set | выборка для выбора настроек |
| Test set | выборка для финальной оценки |
| Accuracy | доля верных ответов |
| Precision | из названных классом `k`, доля верных |
| Recall | из настоящих `k`, доля найденных |
| F1 | среднее гармоническое precision и recall |
| Confusion matrix | таблица «настоящий класс × ответ» |
| He initialization | начальные веса `N(0, 2/n_in)` для ReLU |
| OOD | данные, не похожие на обучающие (out-of-distribution) |

| Calibration | соответствие предсказанных вероятностей реальным частотам |
| Distribution shift | различие между обучающими данными и реальными |
| Data leakage | попадание информации о проверочных данных в обучение |
| Gradient check | сверка аналитического градиента с численным |
